# Decisions

Each entry: date, decision, why. Newest at the bottom.

1. **2026-09-10 · Projects live directly in Apache's web root**, one folder per project next to the shared `potree_libs/`, and Apache serves them as static files. Viewing needs nothing from the Node app, and projects made before the app existed kept working untouched.
2. **2026-09-10 · Rename changes the folder and the link.** One name for both is the simpler model; the cost is that old links break on rename, which the admin panel says.
3. **2026-09-10 · Delete is a soft delete** into the app's own `trash/`, outside the web root. Point clouds take hours to reconvert; disk space is reclaimed only by "Delete permanently".
4. **2026-09-11 · Sessions are stored in files** (`session-file-store`), not in memory: every deploy used to sign the admin out. Keeping the password was chosen over removing it, because the admin panel can't be proven to be unreachable from outside.
5. **2026-09-11 · No CDN caching of point data.** Cloudflare's Free, Pro and Business plans don't cache files over 512 MB, and most projects' `octree.bin` is larger (up to 13.4 GB). A cache-warming feature was built, measured to work for only 4 of 28 projects, and removed: predictable direct serving beats "fast for some, silently not for most". Caching big files would need a different storage backend (e.g. object storage), not cleverer warming.
6. **2026-10-24 · Patch Potree's loader instead of upgrading Potree.** A viewer stopped refining after a few minutes. Edge logs showed requests dropped between the edge and the tunnel, and a sabotage test (1 in 6 requests failing, returning HTML or hanging) froze stock Potree at 4/4 loading slots. The patch (timeout, status checks, worker error handler, 8 slots) recovered from all of them. It is a script applied to the stock file, so the change stays visible and re-applicable.
7. **2026-11-13 · Bounding Box modelled closely on 3Dsurvey's** (the owner's desktop tool): the same mouse and keyboard controls, so nothing new to learn. Box fit uses the `position` range from `metadata.json`, because Potree 2's bounding box is the cubic octree root.
8. **2026-11-13 · Measuring toolbar instead of Potree's sidebar icons**, which clients didn't find. While building it, Potree 1.8's measuring turned out to be broken in current browsers (every point lands on the first); the toolbar script fixes it for the sidebar icons too.
9. **2026-11-13 · Volume is a 2.5D grid against a fitted base plane.** It is simple, fast enough in the browser, exact on synthetic shapes and right for piles and pits. It is wrong for overhangs and multi-level shapes, which the guide says. A triangulated base and filtering of vegetation are open items ([PLAN.md](PLAN.md)). Points are read from the octree directly, so the result doesn't depend on the current view.
10. **2026-11-13 · Load times come from the visitor's browser**, as a request for a 1-pixel image that lands in Apache's log. Apache's log format has no durations, changing it would need root, and only the browser knows when points actually became visible. No extra endpoint, no cookies, nothing leaves the server.
11. **2026-11-13 · Automatic checks on every push**, then deploy only on green: the owner doesn't review code himself, so the checks are the safety net.
12. **2026-11-22 · Node.js 24** (Node 18 is end-of-life). Installed from the official tarball, not the distribution's package, so every supported distribution gets the same version.
13. **2026-11-22 · Renamed to opcviewer and made installable for anyone.** Every installation-specific value is now an `OPCV_*` environment variable; branding is a setting instead of code. The owner's own server was migrated in place: the three script names in 42 existing pages were rewritten and nothing else changed. The same visit checks (status of every link, the viewer's DOM and screenshots of the panels) were identical before and after.
14. **2026-11-22 · Branding is one JSON file next to Potree,** read by every page at load time, not baked into pages. One save updates every project; pages and their golden tests stay branding-free. With nothing set there is no badge, English and the default blue.
15. **2026-11-22 · Licence: AGPL-3.0-or-later.** opcviewer is a network service. Under the GPL, someone could run a modified version for clients without sharing the changes; the AGPL closes that gap.
16. **2026-11-22 · Apache stays the web server** (rather than serving files from Node). It is proven with range requests on multi-gigabyte files, keeps viewing independent of the admin app, and its access log is what the statistics read.
17. **2026-11-22 · The installer uses PotreeConverter's bundled Potree.** The libraries PotreeConverter 2.1.2 ships for its own pages are byte-identical to the ones the owner's server ran (stock `potree.js` SHA-256 `80383869…a4f0`). One pinned, checksum-verified download then covers both the converter and the viewer.
18. **2026-11-22 · One-time setup code for the first password.** Before, the first visitor of a fresh install set the password, so anyone on the network could claim the admin panel between installation and first use. The installer prints a random code that `/api/setup` requires.
19. **2026-11-22 · Root owns the code; the service user owns only what it writes** (web folder, data, uploads, trash), and the installer writes into those as that user. This prevents a compromised service from planting links or code that root would later follow or run during an update. Log access is an ACL for that user instead of the `adm` group, which can read every log on the system.
20. **2026-11-22 · `.htaccess` limited to `FileInfo` and `Options=Indexes`;** links followed only when owners match. That is all the shipped `.htaccess` needs, and the web folder is writable by the service.
21. **2026-11-25 · Volume is calculated on the server, inside the existing app** (approach A, chosen by the owner). Clients on slow connections waited minutes while their browser downloaded tens of MB; the server has the files on its own disk. Apache proxies exactly one address to the app, so nothing else of the admin app becomes public; a separate service (approach B) would have been a second thing to install and watch for little gain. The highlight is still drawn in the visitor's browser, from a compact height grid. Server and browser share one grid module, so the numbers clients already received don't change. One calculation at a time, a short queue and a time limit keep it from slowing the admin panel.
22. **2026-11-25 · Object snap modelled on AutoCAD's OSNAP**, as the owner uses it: the same four snaps, glyphs, F3 and per-type switches, so nothing new to learn.
23. **2026-11-25 · OSNAP on F4, not AutoCAD's F3**, at the owner's request. Nearest added and kept off by default: with it on, a point measured close to an existing line would land on the line instead of the scan, which surprises a client who isn't drawing.
